# koe（声）— 日本語・英語対応 音声AIハーネス

**複数の AI モデルを組み合わせて音声プロダクトを構築するためのハーネス。**
ストリーミング音声認識・話者分離・LLM による議事録生成を一つのプラグイン基盤に統合し、
**レイテンシ・コスト・品質の予算**を明示的に管理します。

## 解こうとしている課題

音声プロダクトは、単一のモデルで完結しません。音声認識モデル、話者分離モデル、LLM、
そして大量の接続コードから成り立ちます。難しいのは個々のモデルではなく、**その組み合わせ**です。

- ライブ字幕とバッチ処理では最適なモデルが正反対になる。この一件はどちらで処理すべきか。
- ベンダーが遅い・誤る・停止したとき、会議の途中で何が起きるのか。
- ある変更が「良くなった」のか「変わっただけ」なのかを、どう判断するのか。
- 音声1時間あたりのコストはいくらで、そのうちどのモデルが原因なのか。

koe は、この4つの問いに対する実装です。

## 動かしてみる

すべて決定論的なモックで動作します。**API キーは不要です。**

```bash
python -m venv .venv && . .venv/Scripts/activate   # Windows
pip install -e ".[dev,api,cli,ja]"
pytest                                              # 413 tests
```

```bash
koe info                    # この環境で利用可能なバックエンド
koe minutes                 # 議事録生成（ガードレールが捏造を検出する様子を表示）
koe evaluate                # 言語別・タグ別にスライスした評価
koe compare --baseline 0.0 --candidate 0.12   # 有意差判定つきA/Bテスト
koe gate                    # CI用の回帰ゲート（失敗時は非ゼロ終了）
koe serve                   # API + Webクライアント（:8000）
```

### Web クライアント

```bash
cd web && npm install && npm run build && cd ..
koe serve      # → http://127.0.0.1:8000
```

マイクがなくても「デモ再生」ボタンで動作を確認できます。サーバー側で合成音声を生成し、
**実際のストリーミングセッション**に流し込むため、音声区間検出・エンドポイント判定・
確定処理・ASR 呼び出しがすべて本番と同じ経路で実行されます。イベントの再生ではありません。

#### 会議室だけでなく、通話も文字起こしする

会議の多くは同じ部屋で行われるものではありません。**設定 → 音声** で取り込み元を
3種類から選べます。

| 取り込み元 | 用途 |
|---|---|
| マイク | 対面の会議。入力デバイスも選択できます |
| 画面・ウィンドウの音声 | オンライン会議の相手側。録音開始時に共有対象を選びます |
| マイク + 画面音声 | ハイブリッド会議。自分の声をマイクから、相手の声を共有音声から |

Windows では、**画面全体またはブラウザのタブ**を共有した場合にのみ音声を取り込めます。
単一のアプリウィンドウには音声が含まれません (Chromium の制限)。この点は選択前に
画面上で明示し、音声トラックのない共有は「無音を文字起こしする」のではなく、
理由を示して拒否します。

同じ画面から、途中結果の更新間隔と、明示的に既定値を解除した場合のみ発話区切りの
2つの値を調整できます。既定値の解除を必須にしているのは意図的です。無音判定の
時間は日本語のほうが英語より長く設定されており、値を送信すればそれを上書きして
しまうためです。送信された値はサーバー側で範囲内に丸められます。

### ローカルモデルで完結させる

API キーもアカウントも不要です。**設定 → ローカル**。

**言語モデル。** Ollama・LM Studio・llama.cpp のサーバー・vLLM・Jan のいずれかを
起動していれば、koe が自動的に見つけます。各プロジェクトが既定で使うポートを
起動時に並行して調べるので、設定する項目はありません。どのモデルを持っているかは
すでにこの PC が知っている情報だからです。

```
Ollama  ·  この端末内
  qwen2.5:7b     7.6B · Q4_K_M
  llama3.2:3b    3.2B · Q4_K_M
```

API キーが登録されている場合は、既定ではそちらが優先されます。キーを貼ったことは
利用者の意思表示ですが、11434 番ポートで何かが待ち受けていることはそうではない
からです。**ローカルを優先する** を有効にすると逆転します。キーを削除しなくても
ローカルだけで運用したい場合のスイッチです。

**音声認識。** ローカル認識を有効にすると、音声はこの端末から一切送信されません。
機密性の高い会議に koe を向けられるのは、この一点によります。
[faster-whisper](https://github.com/SYSTRAN/faster-whisper) をプロセス内で実行します。

```bash
pip install 'koe-harness[asr]'
```

モデルサイズの一覧は、単なる「速度と精度のスライダー」ではありません。koe もそう
提示しません。Whisper の学習データは英語に大きく偏っており、小さいチェックポイントは
限られた多言語能力を英語に近い言語へ振り分けます。その結果 `tiny` と `base` は、
英語なら粗いが使える程度、日本語では使い物になりません。該当するサイズには
**日本語には非推奨** と明示します。会議の文字起こしを見て初めて気づく、という事態を
避けるためです。既定は `large-v3-turbo`。日本語で `large-v3` と1〜2ポイント差の精度を、
3分の1の計算量で出せます。

ローカルの backend は、ルーターを置き換えるのではなく **ルーターに加わります**。
ローカル推論は無料だが遅く、クラウドの vendor は速いが従量課金です。どちらを使うべきかは
まさにルーターが判断するために存在するトレードオフです。そのため各 provider は自分の
不利な点を正直に申告します。費用ゼロで他に重みがなければ、あらゆる選択でローカルが
勝ってしまい、koe は「無料」ではなく「壊れている」と感じられるからです。

> Whisper 各サイズおよびローカル LLM の言語別エラー率は **実測値ではなく事前分布** です。
> 評価ハーネスをその backend に対して実行するまで `ProviderInfo.measured` は `False` のままです。

### API キーの登録

```bash
pip install -e ".[llm]"          # 各社の SDK はオプション依存です
```

アプリの **設定** 画面にキーを貼り付けると、次のリクエストから実際のモデルが使われます。
再起動は不要です。この画面が守っている3つの原則:

| 原則 | 理由 |
|---|---|
| 保存したキーは返さず、フィンガープリント (`sk-ant-…9f2c`) のみを表示する | 秘密情報を読み戻せる UI は、バグ1つで漏洩する |
| 環境変数が保存値より優先され、その場合は編集を拒否する | シークレットを注入する運用環境が、古いファイルに上書きされてはならない |
| 保存では検証せず、**接続テスト** を独立したボタンにする | 検証にはリクエスト費用がかかる。保存が黙って課金するのは驚きでしかない |

キーは利用者の設定ディレクトリにのみ保存され (Windows では DPAPI で暗号化)、
リポジトリには一切含まれません。SDK が導入されていないビルドでは、キーがあっても
モックのまま動作し、その理由を画面に表示します。呼び出して初めて失敗する状態を作りません。

### デスクトップアプリ

[Releases](https://github.com/jon-jc/koe-harness/releases) から
`koe-setup-<version>.exe` をダウンロードして実行してください。
ユーザー単位のインストールなので、管理者権限も UAC の確認も不要です。

> **実行前に Windows の警告が表示されます。** この インストーラーには
> コード署名がありません (証明書は継続的な費用が必要で、本プロジェクトでは
> 負担していません)。そのため SmartScreen が「Windows によって PC が保護され
> ました」と表示し、実行ボタンを **詳細情報 → 実行** の下に隠します。
> これは「危険なファイルである」という意味ではなく「まだ見たことのない
> ファイルである」という意味で、小規模プロジェクトの未署名バイナリでは
> 必ず起きます。
>
> クリックして進む前に、ダウンロードしたファイルを確認してください。
> リリースの `SHA256SUMS.txt` と照合します:
>
> ```powershell
> Get-FileHash .\koe-setup-0.1.0.exe -Algorithm SHA256
> ```

**セキュリティ警告を経由したくない場合** は、インストーラーを使わない方法が
あります:

```bash
pip install -e ".[api,cli,ja,desktop]"
koe-desktop                      # または: python -m koe.desktop
```

どちらの経路でも、サーバー配備と同一の API の上に載るネイティブウィンドウです。
デスクトップ用のスタブは一切なく、2つのビルドが乖離しない構造になっています。

動作要件は Windows 10/11 (x64) と Edge WebView2 ランタイムです。ランタイムは
Windows 11 および更新済みの Windows 10 に標準搭載されています。存在しない場合は
インストーラーが検出し、空白のウィンドウを見せる代わりに入手先を案内します。

Electron ではなく WebView2 上の pywebview を採用しています。クライアントは
すでに存在し gzip 後 14 KB、ブラウザエンジンは Windows に既にあります。
それを動かすためだけに Chromium をもう一つ同梱すれば、得るもののないまま
約 150 MB が増えるだけです。単一インスタンス制御・クラッシュ報告・機能検査に
ついては [docs/desktop.md](docs/desktop.md) を参照してください。

## 設計上の4つの立場

### 1. 日本語は「ロケール設定」ではなく設計制約

多くのバイリンガル・パイプラインが誤る箇所であり、しかも**静かに失敗します**。
数値は正常に見えるのに、意味を持たなくなるからです。

**日本語に WER はほぼ無意味です。** 日本語には語の区切りがないため、「単語」は
選んだ分かち書き器に依存します。同じ音声に対して異なる分割器で 12% の WER を
報告した二つのチームは、同じものを測っていません。koe は日本語を **CER** で評価し、
WER を報告する際は必ず**使用した分かち書き器の名前を併記**します。

**正規化には2つのプロファイルがあり、意図的に分離しています。**

```python
normalize_for_scoring("本日は、ＫＰＩを確認します。")  # → 本日はkpiを確認します
normalize_for_display("本日は、ＫＰＩを確認します。")  # → 本日は、KPIを確認します。
```

評価用は積極的かつ非可逆です。混同すると、認識精度ではなく表記の揺れを測ることになるか、
逆に日本語を読みやすくしている「。」「、」を削ってしまいます。

**空白の扱いは言語依存です。** 日本語に語間空白はないため、ASR が挿入した空白は
恣意的であり除去すべきですが、英語の空白は意味を持ちます。単純な
`.replace(" ", "")` は `hello world` を `helloworld` にしてしまいます。

```
その KPI を review します  →  そのkpiをreviewします
hello world               →  hello world
```

**漢数字変換は形態素解析でゲートします。** 「一般」「一緒」「十分」はいずれも
数詞の漢字で始まりますが数値ではありません。変換すると「1般」となり、
何もしないより悪化します。文字レベルの規則では判別不可能なため、MeCab の品詞
（名詞-数詞）で判定し、MeCab が無い環境では保守的なストップリストに退避します。

**エンドポイント判定も言語ごとに調整しています。** 日本語話者は文末助詞や
丁寧表現（〜ですね、〜ますので）の前で息を継ぎます。英語向けに調整された
エンドポインタはそこで切ってしまい、**否定と時制を担う動詞**が欠落します。
日本語は無音 900ms、英語は 650ms を既定値としています。

### 2. モデル選択は実行時の判断

バックエンドはコスト・速度・想定品質を**データとして**公開するサービスとして登録されます。
リクエストは予算を宣言し、ルーターはまず絶対条件で絞り込み、残った候補を順位付けします。

```python
Budget.realtime()   # ライブ字幕: 800ms以下、ストリーミング必須
Budget.accurate()   # 会議後の議事録: レイテンシ制約なし、最高品質
Budget.bulk()       # アーカイブ再処理: コスト優先、品質下限あり
```

絶対条件は**減点ではなく除外**です。ライブ字幕の 200ms 上限は、
「非常に安いから」で覆せる選好ではありません。

**評価とルーティングは閉ループです。** `record_measurement()` が事前推定値を
実測値で置き換えるため、ベンダーの宣伝値ではなく実態に収束します。

```python
router.select(budget).chosen_name                          # "vendor_a"（推定値）
router.record_measurement("vendor_a", Language.JA, 0.22)   # 本番実測は異なった
router.select(budget).chosen_name                          # "vendor_b"
```

### 3. 不確実性は主張ではなく定量化する

40発話で算出したエラー率は測定値ではなく推定値です。すべての数値にブートストラップ
信頼区間を付与し、A/B 比較には対応のあるブートストラップと並べ替え検定を用います。

```
$ koe compare --baseline 0.0 --candidate 0.12
delta            +10.24%   CI [+8.48%, +12.11%]   p=0.0005  →  REGRESSION

$ koe compare --baseline 0.10 --candidate 0.105
delta            -0.61%    CI [-3.02%, +1.74%]    p=0.6742  →  INCONCLUSIVE
```

リサンプリングは**発話単位**であり、文字単位ではありません。発話内の誤りは強く相関する
ため、文字を独立標本として扱うと分散を大幅に過小評価し、正直とは言えない狭い区間を
生みます。

**回帰ゲートは統計的に有意な劣化でのみ失敗します。** ノイズで発火するゲートは
緑になるまで再実行され、やがて無視されるからです。

**スライス集計にこそ知見があります。** コーパス全体の CER は、対処可能な事実を平均で
覆い隠します。

| スライス | n | CER |
|---|---|---|
| 全体 | 41 | 8.40% |
| tag:monolingual | 32 | 7.83% |
| **tag:code-switch** | 9 | **10.59%** |
| lang:ja | 28 | 10.20% |
| lang:en | 13 | 6.42% |

### 4. 根拠検証を文字列操作にする

<a name="根拠検証を文字列操作にする"></a>

LLM に会議を要約させると、誰も合意していないアクションアイテムを作り出したり、
誰も言っていない期限を付けたりすることが稀に起こります。しかもレビュアーが
読み飛ばす程度には自然な文章で。議事録プロダクトにおいて、その捏造タスクは
期限付きで誰かのバックログに入ります。

そこで**スキーマは、すべての主張に逐語引用（`source_quote`）を必須としています。**
この一点により、幻覚検出は文字列操作になります。引用が文字起こしに存在するか、
しないか、それだけです。二度目のモデル呼び出しも、LLM 判定器自身の不確実性も、
実質的なコストも不要です。

照合は評価用正規化を通した上で行うため、逐語コピーでも全角・半角や句読点が
揺れた引用が一致します。一致度は二値ではなく**最長共通部分列**で採点するため、
軽く言い換えられた引用は 0.9 前後、捏造は 0 付近となり、前者を残して後者を落とせます。

根拠のない主張は**印を付けるのではなく削除**します。「未検証」と表示された
アクションアイテムも結局はタスクリストに入り、読み手には確認手段がないからです。

## 信頼性の保証

| 保証 | 理由 |
|---|---|
| 後処理は必ず完走する | 失敗した1つの解放処理が兄弟の解放を止めてはならない |
| 子スコープは親より先に破棄される | デコーダが音声バッファを持つセッションより長生きしてはならない |
| 購読側のクラッシュで音声を落とさない | ハンドラの失敗は emit 単位で隔離される |
| 確定した字幕は決して書き換えない | 読者が既に読んだ文字を取り消すのは、待たせるより悪い |
| 音声取り込みは認識処理でブロックしない | 遅いモデルを待って発話を落とすのは回復不能 |
| 満杯のサーバーは待たせず即座に拒否する | 待たされた発信者は誰も処理していない音声を録音し続ける |
| リトライ不可のエラーはフォールバックを止める | 不正なリクエストは次のプロバイダでも同じく失敗する |
| サーキットブレーカはリトライ可能な失敗でのみ開く | 不正リクエストはプロバイダの健全性を示さない |
| 設定不備の本番プロセスは起動を拒否する | ワイルドカード CORS はデプロイを止めるべきで、障害になるべきではない |

## 意図的な制約

過大な主張をするリポジトリは、控えめなものより信頼を損ないます。
レビュアーは5分で気づくため、先に明記します。

- **既定のバックエンドは決定論的なモックです。** Anthropic・OpenAI・
  （プロトコル経由で）Whisper/pyannote の実アダプタは存在しますが、CI とデモが
  動かしているのはモックです。これは意図的で、CI を無償かつ決定論的に保ち、
  クリーンなチェックアウトで動作させるためですが、報告されるエラー率は
  **ハーネスの測定値であって、実モデルの性能ではありません**。
- **コーパスは41発話の合成データです。** 日本語パイプラインが壊れる事例を
  意図的に含めて記述したもので、機構の検証には十分ですがベンチマーク結果では
  ありません。実録音への差し替えはデータの変更であり、コードの変更ではありません。
- **セッションはプロセス内に存在します。** ALB はスティッキー設定、スケールは
  タスク単位の水平方向です。インスタンス間のセッション移行には共有ストアが必要で、
  現状は持っていません。
- **DER の話者対応付けは貪欲法**であり、ハンガリアン法ではありません。各参照話者に
  対して1つの仮説ラベルが優勢な場合（会議では通常こうなります）は厳密解と一致し、
  それ以外でも近似解となります。
- **Terraform は検証済みですが未適用です。** CI で `fmt` と `validate` を実行して
  いますが、実際の AWS アカウントには適用していません。
